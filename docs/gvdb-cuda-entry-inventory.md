# Retained CUDA entry inventory

Status: review inventory, 2026-10-19. Reference retirement remains blocked on the project's acceptance gates. The machine-readable [entry inventory](gvdb-cuda-entry-inventory.json) accounts for all **100 explicit `__global__ void` declarations** currently found in the retained GVDB `.cu`/`.cuh` tree, keyed by source path plus entry name. Repeated SPH/scan names in different files are separate entries. Replacement file paths were checked on disk. Device helpers, CPU adapters, macros and graphics/presentation shaders require their own disposition; this is not a claim of exhaustive source-level parity.

The grouping records implementation roles, not positional CUDA ABI compatibility or permission to remove code. Several old kernels can share one Slang algorithm, while one old kernel can need several new stages. These counts are not a completion percentage:

| State | Entries | Meaning |
| --- | ---: | --- |
| owned-validated | 28 | Public volume-backed operators and device queries passed recorded Windows tests; platform and consumer gates remain. |
| sample-validated | 12 | Migrated sample paths exercise these replacement roles; public ownership and broader acceptance remain. |
| portable-foundation | 30 | A portable helper/program exists; the listed public contract or integration work remains. |
| partial | 24 | Related functionality exists, but the old behavior is not fully covered. |
| pending | 6 | No completed replacement/disposition is claimed. |

The six pending entries are `gvdbScatterPointDensity`, `gvdbScatterPointAvgCol`, `gvdbAddSupportVoxel`, `gvdbMapExtraGVDB`, `gvdbRaySurfaceTricubic`, and OptiX `__exception__main`. The last requires an explicit diagnostic/backend disposition, not necessarily a one-to-one public shader stage.

Other material gaps are explicit in the JSON: normalized-ushort level-set color needs inverse-distance weighting and a zero-distance rule; ordinary gather after quantization does not cover it. Public reduction now excludes inactive/unused slots and aprons, including poisoned imported data. Public point topology uses checked signed host candidates and does not inherit the separate GPU key helper's nonnegative 16-bit limit. Section/compositing and individual raycast/RT shading modes need separate legacy-equation/control/visual acceptance. The existing PIC/FLIP transfer utility is not a complete FLIP solver; the retained fluid samples use SPH.

The public point factory (`f18a6b9`), authenticated append candidate (`ca793cc`), first owned renderer (`b2f1185`) and retained-snapshot reduction (`4d0ee12`) are committed and validated. The custom renderer now also adopts owned snapshots (`8727803`). Public owned dense-to-sparse resampling also passes four-backend, native-validation, CUDA memory, and installed-consumer checks. Ordinary density/level-set gathers now publish owned channels with stable point association and independent support/distance radii. Depth-map also adopts public snapshots (`ea973c9`) while preserving its graphics/CUDA interop image results. Regional downsampling now has a public device-only query with explicit caller completion, exact endpoint division and Vulkan RTE32 controls, validated on both NVIDIA and AMD graphics. The resample application now consumes the public downsample query, host topology/halo, owned resample publication and raw snapshot viewer. 3d-print also publishes through the public owner/resample APIs and raw snapshot viewer, while its portable mesh-voxelizer helper remains outside the public operator contract. Other consumer and operator migrations remain active. The current project execution records and remaining gates live in the aggregate repository's `docs/slang-next-status.md` and `docs/plans/2026-10-18-gvdb-unified-volume-ownership.md`. Keep `ETHEREAL_BUILD_GVDB_LEGACY` and its sources until those gates are satisfied, including Linux, real multi-GPU routes, consumer ownership, visual comparisons and performance checks.
