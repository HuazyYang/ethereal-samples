# Portable point-cloud reconstruction helpers

**Branch-order correction:** the legacy `fromBranching(r4,r3,r2,r1,r0)` call ends in 4, so its leaf width is 16. The implementation and topology fixtures use leaf-first `{4,3,3,3,3}`. Corrected analytic and full-asset reconstruction pass on all four APIs. Earlier leaf8 memory, rendering and sanitizer measurements are superseded. Corrected reconstruction sanitizer checks pass; current application captures are recorded separately in the sample README.

The application now uses these helpers and the unified NVRHI runtime. The previous application is preserved as `legacy-main.cpp`; `SceneFile.*` is unchanged for legacy builds. See [README.md](README.md) for supported renderers, controls and application validation. Reconstruction references and cross-API tests do not establish image equivalence with the legacy renderer.

- `PointCloudScene` retains the original scene defaults, material fields, model transforms, camera/light orbits, frame patterns and literal directory prefixes. Materials use the shared SDK-free `sample-utils/SceneMaterial.h`. Set `SceneDesc::renderScale` before parsing to retain a command-line override; resolve the original zero/unset scale to 1 and negative/unset frame to 0 in the application.
- `PointCloudInput` loads little-endian count/bounds/ushort3 frames and exposes a CPU decoder for references. Constant axes and odd point counts are valid. NaNs, infinities, reversed bounds, incomplete triples and truncated payloads fail explicitly. Legacy trailing extension bytes remain accepted.
- `PointCloudReconstruction` dispatches portable Slang conversion, bins unquantized positions, re-quantizes subcell positions to normalized ushort3, gathers a radius-1 level set, updates boundary-3 aprons and applies optional smoothing. Call `reconstruct` for each loaded frame. Successful calls replace the previous volume; failures preserve its state. No CUDA or OptiX SDK types appear in these APIs.

The fixed original reconstruction settings are leaf width 16, topology support radius 2, subcell width 4, level-set radius 1 and maximum distance 3. `FP16` in the original sample means normalized unsigned 16-bit, not half-precision floating point. Positive-coordinate quantization preserves padded/clamped bounds; negative axes use signed padded bounds and retain all points rather than silently dropping them. Compact atlas packing may differ from the original 32x32 initial atlas without changing world-space topology.

`pointLines()` supplies the original overlay glyphs: at most 250,000 lines, sampled with `ceil(pointCount/250000)`, length `(0.5,0.5,0.5)` and color `position/256`. Host positions and the matching GPU buffer are also exposed for presentation. The application maps materials, environment, progressive sampling and mixed geometry to the shared `SlangSceneRT` renderer.

It defines `gvdb_point_cloud_input`, `gvdb_point_cloud_reconstruction`, `gvdb_point_cloud_input_tests`, and `gvdb_point_cloud_reconstruction_tests`. The latter accepts the existing `-dx11`, `-dx12`, `-vk`, or `-cuda` selector; add `--asset <assets-directory>` for the full `points.dat`/`teapot.scn` case. Test registration covers the CPU input/parser test and analytic plus real-asset reconstruction on every built backend.

Validation: the CPU input/parser fixture passes, and the corrected analytic reconstruction and full `points.dat`/`teapot.scn` reconstruction pass on all four APIs. Shader entries compile to DXBC, DXIL, SPIR-V and PTX. Corrected CUDA Compute Sanitizer runs report zero errors for both analytic and full-asset reconstruction.

Analytic tests compare every allocated voxel and apron against an independent CPU gather/smoothing reference, include signed/constant/odd-count inputs, and reconstruct two disjoint frames to detect accumulation. Compression is tested separately against CPU normalization with a maximum difference of one ushort code; GPU division can round across a truncation boundary. Gathering and smoothing then use the verified decoded codes with a tight `5e-5` absolute tolerance. This distinguishes compression rounding from stencil correctness.

The full asset produces 14,583 active leaf16 bricks on all four APIs. The analytic fixture independently enumerates every integer support voxel and compares the complete leaf-origin set; it also asserts leaf16/apron18. It additionally checks eight independently reconstructed occupied voxels using CPU conversion, quantization, gathering and smoothing. Its tolerance is one ushort quantization interval plus 0.002, accounting for backend rounding at large world coordinates. Observed maximum errors were `6.30e-5` (D3D11), `4.75e-5` (D3D12), and `4.05e-5` (Vulkan/CUDA). Negative voxel counts differ slightly between APIs near zero; bit-identical atlas values are not claimed.
