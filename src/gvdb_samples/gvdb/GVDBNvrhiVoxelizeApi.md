# Public mesh voxelization

The additive `GVDBNvrhiVoxelizeApi.h` interface classifies a dense X-fast grid independently of volume ownership. `GVDBMeshVoxelize.slang` retains the conservative triangle and parity algorithm, with exact geometric binary32 division and explicit Vulkan RTE32. The previous `GVDBVoxelize.slang` remains a separate reference. 3d-print consumes both public recording/completion phases before sparse publication.

Call `prepare`, `recordCounts`, submit and wait, `finishCountsAfterCallerCompletion`, `recordVoxelization`, submit and wait, then `finishAfterCallerCompletion`. The completion calls never submit or explicitly wait; their caller must establish completion before mapping staging buffers. Checked CPU prefix offsets are metadata preparation. Recording does not imply completion. A successfully recorded phase is consumed even if the caller subsequently discards its command list. Calls on one operator/ticket require external serialization.

Preparation copies Float4 vertices (all components finite, W ignored geometrically) and flat uint32 triangle indices. Empty lists are allowed and produce exterior fill. All dimensions are positive; at most UINT32_MAX/4 voxels, UINT32_MAX/16 vertices and UINT32_MAX/4 indices. Indices must form complete triangles in range. Output formats are R8_UINT, R32_FLOAT and R32_SINT; integer values truncate toward zero and must fit before conversion. Values W and descriptor reserved fields are zero. Packed R8 padding bytes are zero; borrowed CPU/GPU spans expose only logical bytes.

The numerical contract retains conservative triangle/box overlap, positive-X oriented top-left parity and a +1/64 normalized Y nudge at integer coordinates. Surface classification takes precedence. Closed consistently triangulated geometry is needed for meaningful parity interiors; degenerate/open/self-intersecting inputs have the shader's geometric result, not a repaired solid. CUDA parity multiplies/adds use explicit round-to-nearest intrinsics; graphics use precise operations and Vulkan declares RTE32. Geometric divisions use a portable uint32 mantissa/remainder algorithm with nearest/ties-to-even rounding. Exactly aligned cube faces touch both adjacent cells; this corrects a reproduced AMD DX11 corner omission caused by approximate division. The integer helper preserves signed-zero, subnormal and overflow result bits; subsequent native float operations retain target denormal behavior. Affine dot products and SAT still use native arithmetic, so no universal bit-identical arbitrary-boundary or legacy CUDA parity promise is made. No epsilon substitution is introduced by this API.

Conservative finite-operation validation rejects extreme cancellation/coordinates: each voxel width is at least 16*FLT_MIN; the absolute bound on a center is at most 1e30; twice that bound and twice the sum of that bound plus absolute affine terms, divided by voxel width, must be at most 65536. This leaves a wide margin for the triangle tests' intermediate products. Large translated scenes may need rebasing even if their local extent is small.

Budgets bound copied input bytes, total retained NVRHI buffer descriptor bytes (not driver allocation granularity), 14 buffers, twice triangleCount*binCount and voxelCount*triangleCount. Bin count is min(resolution.y,65535*256). Initial bytes are 256 + max(16,16*vertexCount) + max(4,4*indexCount) + 8*binCount + 108 dummy bytes. Completed allocation adds 4*binCount + 48*max(1,totalReferences) + twice the aligned dense byte count. Preparation checks minimum second-stage cost; count completion checks actual triangle references and the complete budget. CPU host vectors and driver overhead are outside the device allocation budget. Triangle count cannot overflow per-bin uint32 atomics under the input limit; prefix totals must fit UINT32_MAX/48.

Tickets authenticate their originating factory. Out-of-order/repeated recording or completion fails; output descriptors stay unchanged on failure, while raw factory/prepare outputs are cleared. Count completion allocates into temporary handles and commits only on success. Tickets retain kernels/device/resources for both completion stages after factory release. Factory release before the second recording leaves a completable count result but does not permit another factory to record it. Borrowed result storage survives until ticket release. GPU output access is available after second recording and requires caller ordering before consumption.

Build integration includes four offline artifacts for DXBC, DXIL, SPIR-V and PTX when the shader compiler helper is available. Factory creation validates each entry's group size, all nine resource slots/types/strides and the complete 128-byte constants layout, including the three-row array. The ABI boundary exports no STL types. No CUDA runtime API, submission wrapper or host interop fallback is introduced.

The division algorithm has an independent 250,035-pair CPU oracle and 4,131 fixed GPU bit goldens, including signed zero, subnormal and overflow cases. The geometric suite covers all formats, winding reversal, translated negative bounds, affine scaling, integer-aligned faces, out-of-grid triangles, exact empty allocation limits, both graphics adapters and CUDA memory checking. Installed consumer checks use only installed public headers and NVRHI. Broader performance, Linux, legacy visual/equation equivalence and reference retirement remain separate gates.
